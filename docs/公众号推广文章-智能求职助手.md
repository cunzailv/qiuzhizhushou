## 二、正文

### 【开篇】

上周有个朋友问我：你投了多少家了？

我说，不知道，大概三百多吧。

他笑了：那你收到几个面试？

我沉默了。因为我知道答案——不到十个。而这三百多份简历里，至少有一半，我连岗位要求都没读完就点了「立即沟通」。

这大概是很多人找工作的真实状态：

**打开招聘软件 → 看到薪资还行 → 扫一眼岗位名称 → 点沟通 → 复制粘贴一段打招呼语 → 下一家。**

一天能投五十份，看起来很努力。但 HR 那边收到的是什么？是五十条一模一样的、没有任何信息量的「您好，我对这个岗位很感兴趣」。

**海投的本质，不是投得多，是投得糊。**

后来我换了个思路：与其投三百份糊的，不如投三十份准的。而"准"这件事，人脑做不动——你得读 JD、比对简历、判断匹配度、想清楚差在哪、再决定要不要投。一家五分钟，三十家就是两个半小时。

所以我把这件事交给了机器。

这就是今天要介绍的 project：**智能求职助手**——一个跑在浏览器里的开源求职工具。

### 【第一节】它是什么：不是投递机器人，是"投前参谋"

先划清一个认知：市面上讲自动投递的工具不少，但大多数解决的是"手累"，不解决"投错"。

智能求职助手的定位，是**在你按下"沟通"之前，先替你想清楚三件事**：

1. **这个岗位，我到底配不配？**（匹配度打分，0–100）
2. **如果不配，差在哪、能不能补？**（差距报告 + 改进建议）
3. **如果配，怎么开口才不像群发？**（个性化话术生成）

它的形态是一个 Chrome / Edge 浏览器扩展。装好之后，你不需要改变任何习惯——照常打开 Boss 直聘、猎聘、前程无忧、智联招聘、脉脉，它会在页面右下角浮出一个小窗，安安静静地帮你算分、帮你筛、帮你打招呼。

> 【配图 1｜位置：本节第 2 段后】
> **素材**：`docs/assets/logo-transparent.png`（握手徽章）
> **用途**：建立品牌记忆点，说明"握手"寓意——平台与求职者、AI 与用户之间的双向连接。

**一句话总结它的定位：**

> 它是你投简历之前的"参谋"，不是替你投简历的"枪手"。

这个区别很重要。参谋给你判断，枪手替你决策。前者你越用越清醒，后者你越用越糊涂。

### 【第二节】核心功能：四件事，它替你干了

#### 1. 把简历"读薄"，把岗位"读透"

上传一份 PDF 或 DOCX 简历，它会解析成结构化画像：工作年限、项目经历、技能清单和熟练度分级、个人亮点。

同时，每打开一个岗位详情，它会把 JD 也拆开：职责是什么、硬性条件是什么、哪些是加分项、薪资学历年限的门槛在哪。

**这一步的价值在于：让"我觉得还行"变成"我确认匹配"。**

很多人投错岗，不是因为能力不够，是因为压根没看清要求。JD 里写着"需 3 年以上 To B 经验"，你两年 C 端经验，投了也是白投——但你就是没看见那行字。

机器不会漏看。

#### 2. 三道关卡的匹配评分

评分不是让大模型瞎感觉，而是三层过滤：

| 层级 | 做什么 | 特点 |
|---|---|---|
| 第一层 · 本地规则初筛 | 学历、年限、薪资、地点等硬门槛 | 秒出结果，**不花钱** |
| 第二层 · 硬门槛拦截 | 明确不满足的条件直接判负 | 避免"陪跑式投递" |
| 第三层 · LLM 语义精评 | 理解岗位真实意图与简历亮点 | 输出 0–100 分 + 理由 |

这个设计的巧思在顺序上：**先用不花钱的方式干掉 70% 的无效岗位，再让 AI 认真看你真正该看的那 30%。**

结果是——你省时间，也省 token。它甚至内置了每日 AI 预算上限，防止你哪天一激动把额度烧完。

#### 3. 差距报告：不只告诉你几分，还告诉你差哪

这是我觉得最"值钱"的功能。

一个光秃秃的"72 分"没有意义。有意义的是下面这段：

> 技能匹配：岗位要求 Kubernetes 实操，你的简历只体现了 Docker 单机部署 → 建议补充容器编排相关项目描述
> 经验匹配：要求 3 年，你 2 年 8 个月，属于可接受区间 → 无需处理
> 学历匹配：满足
> **简历改写要点**：把"负责服务部署"改为"负责 20+ 服务容器化改造，基于 K8s 完成灰度发布"

**分数是用来筛的，差距报告才是用来改的。**

投不上的岗位，它告诉你差在哪，你下次就知道补什么；能投的岗位，它告诉你简历该怎么调，命中率立刻不一样。

#### 4. 会记住你的"管家 Agent"

这是它区别于普通脚本的地方——它有一套多角色 Agent：

- **选岗 Agent**：按你的画像和目标，挑出值得投的
- **策略 Agent**：生成打招呼话术，不是模板，是结合岗位和你的经历写的
- **沟通 Agent**：批量执行，支持"按分筛选后再沟通""不评分直接沟通"等模式
- **跟进 Agent**：投完之后盯状态——已读、沟通中、邀约、不合适
- **复盘 Agent**：一段时间后回头算账，哪种岗位回复率高，反哺下一轮策略

而且它有**记忆**。你告诉它"我不考虑外包""通勤超过一小时的不看"，它记下来，跨会话生效，不用每次重复。

### 【第三节】使用场景：四种人，四种用法

#### 场景一｜应届生 / 校招海投期

投递量大、时间紧、对岗位判断力弱。用法是：**让分数帮你排序**。同一批岗位，先投 80 分以上的，60 分以下的直接放弃，把有限的精力压在头部机会上。

#### 场景二｜转行 / 跨岗

最怕的不是被拒，是不知道被拒的原因。用法是：**把差距报告当学习清单**。连续看十个岗位的差距项，你会发现高频缺失的技能就那么两三个——那就是你该补的。

#### 场景三｜在职，偷偷看机会

不能大张旗鼓，也没时间天天刷。用法是：**设置好筛选条件，让它自动盯**。岗位、地点、薪资、学历、关键词排除一次配好，看到合适的再手动确认。全程本地运行，不留痕迹在公司的电脑之外。

#### 场景四｜面试前后的复盘

投了三十家，只有三家回。是人不行，还是策略不对？用法是：**看漏斗，不看总量**。

```
已投递 30 → HR 已读 12 → 沟通中 6 → 面试邀约 3 → 已录用 ?
```

如果已读率低，是打招呼语的问题；如果已读高但沟通断，是话术或简历的问题；如果沟通到邀约断，是岗位匹配本身的问题。**每一层流失，指向不同的病因。**

### 【第四节】亮点价值：为什么值得你花十分钟装一下

#### ① 它把"努力"变成了"可衡量的努力"

以前你的努力是"今天投了 50 家"。现在你的努力是"今天投了 8 家，平均分 84，两个已读"。

**前者只会让你更累，后者会让你更准。**

#### ② 数据在你自己电脑里

简历、投递记录、沟通状态，全部存在浏览器本地数据库（IndexedDB），不上传任何第三方服务器。AI 调用走你自己配置的模型接口——DeepSeek、OpenAI、通义千问、GLM-4、Kimi 等十几种预设，也可以填自己的兼容接口。

**找工作这件事本身就够私密了，工具不该再给你添一层担心。**

#### ③ 五个平台，一个入口

Boss 直聘、猎聘、前程无忧、智联招聘、脉脉，一站打通。不用在五个 App 之间反复横跳，也不用记五个平台的投递进度。

### 【第五节】三步开始用

它是开源的，没有应用商店上架，所以需要手动装一次——大概三分钟。

**第一步**：打开 GitHub 仓库 `cunzailv/qiuzhizhushou`，克隆到本地。

**第二步**：执行 `npm install` 和 `npm run build`，得到 `dist` 目录。

**第三步**：浏览器地址栏输入 `chrome://extensions/`，打开右上角「开发者模式」，点「加载已解压的扩展程序」，选中 `dist` 目录。

装好之后：点开插件 → **简历** → 上传 PDF/DOCX → 设为默认。然后随便打开一个招聘网站，右下角就会出现那个小浮窗。

**接下来的事，它会告诉你。**
